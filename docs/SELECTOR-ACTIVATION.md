# Optional admitted finite selector

Dirty Mode construction: source only, runtime unverified. No adapter, fake,
journal, model, connector or test has been executed. All seven arms remain
NOT MEASURED; finite selections are not evidence of model quality or live eligibility.
The ordinary inspect/explain CLI and offline src/iac_review imports are unchanged.

`AdmittedSelector` implements the actual core `SelectorPort.select(ExplanationCapsule)
-> ExplanationResponse`. Its default is disabled. Constructor and disabled calls
create no journal, attempt, provider, key lookup or network request. A disabled or
rejected call returns a strict empty-clause response; the core `validate_selection`
then returns its exact deterministic fallback with every original limitation.
The adapter never renders arbitrary model text or changes a product finding.

Pure `make_binding` accepts the actual shareable report, opaque finding ID, pinned
D ArmRow and Context, separately expected report/D digests and an authority reference.
It rebuilds the actual core capsule, checks the case/resource/rule/outcome/decision
facts/limitations/source/build joins, and keeps only detached finite capsule and
D metadata. External callers pin `binding_digest(binding)` independently. Hash
agreement identifies records, not genuine author/execution/approval identity;
an authentic external owner must approve those pins. No detector-derived gold or
case-record/raw/request hash substitution supplies authority.

Enabling the adapter additionally requires that binding pin, an explicitly supplied
transport and an exclusively owned existing journal with matching provider/model
price. Before requesting anything, the adapter reconstructs incoming and stored
capsules through the core finite fact filter and requires exact equality. This
revalidates mutable nested lists as well as IDs, facts, order, baseline prose and
required limitations. Arbitrary private strings/tags/addresses, foreign or reversed
facts and trusted-looking replacements are refused. Shareable/authority/D metadata
never enters inference; only the exact core L capsule and frozen L instruction do.

The shared `experiment.execute_attempt(*, arm, payload, finding_id, context,
transport, journal, limits, validator, capture_private_prose=False)->Observation`
contains the original executor's one-start/one-terminal accounting path.
run_experiments retains its public signature and invokes the same helper. The
selector calls it once with L, clamps the finite input/output byte limits, and
uses max_attempts=1. It cannot invoke P/M, rerun detectors, start a second attempt,
retry, create another ledger or reconcile billing. Canonical request/projection,
raw source, price, config and pending-liability meanings are unchanged.

Successful replies must survive the real strict ExplanationResponse wire and core
finite validator before return. Unknown templates, free-text extras, omitted facts,
reversed transitions, missing limitations, malformed/partial/refused/error/timeout
responses, caps and activation failures use core fallback. The same attempt path
retains all started/failed charges, reported tokens and unresolved upper bounds.
Zero-start denied calls produce no Attempt receipt. Payload-free SelectorReceipt
records are views of those existing Attempt records, not a second balance ledger.
If terminal persistence fails, no replacement receipt/retry is invented:
unrecorded_attempt_possible remains true and the actual journal needs operator review.

ProviderTransport still requires its own externally approved activation and exact
per-attempt durable-start permit before keys/connector creation. An enabled selector
alone authorizes no provider access. Every selector attempt is live-ineligible,
including future genuine responses, until separate measurement admission.
External approval authenticity, concurrency/crash behavior, actual provider/OS
limits and all regression/integration tests remain deferred. Injection is trusted
code, not a sandbox; no such injection was run during construction.

The optional programmatic journey is
`explain_with_admitted_selector(report: ReviewReport, finding_id, *, selector=None)
-> ExplainedFinding`. It uses the actual report's shareable projection and core
capsule builder; it never opens the private map, source plan or scanner/gold payload.
With no selector or a different frozen report pin, it returns exact deterministic
fallback with no call. With an admitted matching selector, it makes that one L call
and passes the returned finite wire through core validation again. The result includes
the same opaque finding, rule/outcome, report digest and unchanged exit code, safe
finite SelectionResult and only the new call's actual payload-free receipt (or None).
The original report is not edited. A report/exit mutation by trusted injected code
is refused explicitly after preserving any started attempt in the journal.

Regression SOURCE composes a synthetic saved plan with actual load_plan/evaluate/
build_report, binds one finding, then describes valid/invalid same-finding selection,
D/exit/severity/coverage invariance, private canary exclusion, no P/M calls, shared
request caps, pending timeout even with reported accounting, price refusal and denied
zero-start paths. Those functions/tests have not run; no example report, explanation,
receipt or model result was generated. No CLI or default provider activation was added.

SelectorBinding, SelectorReceipt and ExplainedFinding are internal/private evaluation
metadata wrappers, not public report schemas or authority attestations. A display
consumer can use the core finite SelectionResult; it must not publish journal/cost/
context/approval metadata simply because it accompanies safe explanation text.
